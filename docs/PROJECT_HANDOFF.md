# 1. 项目目标

制作一个：

**横屏、单机、无尽模式、回合制的"植物合成 + 五路防线"小游戏。**

核心体验不是传统实时塔防，而是：

> 玩家每进行一次棋盘操作，所有植物齐射一次，然后所有敌人向左推进一格。

玩家拥有无限思考时间。

如果玩家不进行操作：

**游戏世界完全静止。**

不存在实时倒计时。

---

当前开发方向：

- TypeScript
- Phaser 3
- Vite
- 横屏 Web 版本优先
- 后续可通过 Capacitor 包装 Android / iOS
- 完全离线
- 不需要服务器

```text
1920 × 1080
16:9 横屏
```

Android 也以横屏为目标。

# 3. 游戏不是关卡制

这是非常重要的设计约束。

本游戏：

```text
无尽模式
```

不存在：

- 第1关 / 第2关
- 三星评价
- 关卡地图
- Boss关
- 通关动画
- 生命3颗心
- 能量8/20
- x2 / x4 游戏速度
- 波次倒计时

可以存在越来越强的敌人，但这是：

```text
无尽难度增长
```

而不是"关卡"。

固定：

```text

```

五行分别对应五条战斗 Lane。

```text

│     │     │  Lane 2

│     │     │  Lane 4
├─────┼─────┤
│     │     │  Lane 5
└─────┴─────┘
```

## 绝对规则

**植物永远只能存在于这 2×5 植物区。**

植物绝对不能：

```text

```

右侧战场只允许出现：

- 敌人
- 奖励球
- Projectile
- 特效

# 7. 回合机制

本游戏本质上是：

```text
Turn Based
```

玩家拥有无限思考时间。

一次合法操作：

```text
= 1 Turn
```

标准 Turn：

```text
玩家进行一次操作
↓
棋盘状态更新
↓
所有植物一起攻击
↓
Projectile结算
↓
敌人死亡 / 奖励球获取
↓
所有存活敌人向左移动1格
↓
可能生成新敌人
↓
画面完全停止
↓
等待玩家下一次操作
```

---

# 8. 什么操作会消耗 Turn

以下属于合法操作：

### A. 植物移动到空格

```text
64 → 空格
```

消耗1 Turn。

---

### B. 两个不同植物交换

例如：

```text
32 ↔ 64
```

消耗1 Turn。

允许同一行左右交换。

---

### C. 两个相同植物合成

例如：

```text
64 + 64
→
128
```

消耗1 Turn。

---

### D. 出生槽植物放到空格

消耗1 Turn。

---

### E. 出生槽植物直接与棋盘同值植物合成

例如：

```text
出生槽64
+
棋盘64

→128
```

消耗1 Turn。

---

## 非法操作

取消拖动、拖到不可操作位置：

```text
不消耗 Turn
```

---

# 9. 攻击发生在操作之后

这一点已经确认。

例如：

```text
64 + 64 → 128
```

本Turn攻击的是：

```text
新的128
```

不是两个旧64。

同样：

如果把256从 Lane1 移动到 Lane4：

本Turn它直接：

```text
攻击 Lane4
```

不是 Lane1。

统一原则：

> 先执行玩家操作，再按照新的棋盘状态发动攻击。

---

# 10. 所有植物每Turn全部攻击

非常重要。

不是：

```text
只有被移动的植物攻击
```

而是：

```text
整个2×5植物区中的所有植物
每Turn全部攻击一次
```

例如 Lane2 有：

```text
32 + 16
```

那么本Turn：

32和16都进行攻击。

# 13. Projectile 数量规则

已通过视频进一步确认。

植物攻击时：

```text
Value = 1
→ 1颗子弹
→ 每颗1伤害


Value = 2
→ 2颗子弹
→ 每颗1伤害


Value >= 4
→ 固定4颗子弹
```

统一公式：

```ts
projectileCount = Math.min(plantValue, 4)

damagePerProjectile =
plantValue / projectileCount
```

例如：

```text
4   = 4 × 1
8   = 4 × 2
16  = 4 × 4
32  = 4 × 8
64  = 4 × 16
128 = 4 × 32
256 = 4 × 64
```

---

# 14. Projectile 的视觉方向

四颗子弹必须：

**沿 Lane 前后排列。**

正确：

```text
植物    ●    ●    ●    ●   →→→
```

错误：

```text
●
●
●
●
```

也就是说：

四颗Projectile沿道路方向：

```text
水平飞行
与道路平行
```

每颗可以间隔几十毫秒发出。

---

# 15. Projectile 穿透怪物

每颗Projectile拥有：

```ts
remainingDamage
```

例如：

```text
64植物
=
4颗Projectile
每颗16 Damage
```

如果一颗16伤害Projectile：

遇到5血敌人：

```text
Enemy HP 5 → 0

Projectile remainingDamage:
16 - 5
=
11
```

该Projectile：

```text
继续向右飞
```

并不是杀敌后整颗Projectile消失。

---

# 16. 怪物不会吃掉整颗Projectile

标准规则：

```ts
if (remainingDamage < enemy.hp) {

    enemy.hp -= remainingDamage

    destroyProjectile()

}

else {

    remainingDamage -= enemy.hp

    killEnemy()

    if (remainingDamage > 0) {
        continueProjectile()
    }
}
```

因此：

**攻击怪物时，过量伤害可以继续向后传播。**

---

# 17. 奖励球规则完全不同

RewardBall 会：

**直接吃掉整颗Projectile。**

例如：

```text
Projectile remainingDamage = 64

RewardBall value = 1
```

碰撞后：

```text
获得RewardBall 1

Projectile直接销毁
```

剩余64伤害：

```text
全部浪费
```

# 22. 出生槽

出生槽：

**独立于2×5植物区。**

一次只显示一个值。

它不是普通队列。

它更接近：

```text
Max Register
```

规则：

```ts
slotValue =
max(
    currentSlotValue,
    rewardsCapturedThisTurn
)
```

例如：

```text
出生槽1
捕获8

→出生槽8
```

---

例如：

```text
出生槽8
捕获1

→仍然8
```

---

例如：

同一Turn捕获：

```text
1
2
4
8
```

最终：

```text
出生槽8
```

---

相同值：

```text
出生槽4
+
捕获4
```

不会自动：

```text
4+4→8
```

而是仍然：

```text
4
```

# 31. 核心策略体验

这是开发时最重要的产品理解。

玩家经常遇到：

```text
很多64占满棋盘
```

64+64可以得到128。

虽然：

```text
64+64 = 128
```

总攻击值没有变化。

但合成之后：

```text
占位减少
```

同时：

```text
火力集中在某一Lane
```

这导致：

> 合成提高火力密度，却降低多Lane火力分配灵活性。

例如：

三个Lane同时有危险。

一个256虽然强：

```text
只能放在一条Lane
```

这就是游戏最主要的决策张力。

---

# 32. 玩家经常进行"剩余Turn计算"

例如：

敌人：

```text
HP = 180
距离防线 = 3格
```

Lane火力：

```text
32 + 16
=
48
```

理论三Turn：

```text
48 × 3 = 144
```

杀不死180。

玩家必须：

- 调植物
- 合成
- 从出生槽加入植物

才能活下来。

这就是游戏核心。

---

# 33. RewardBall 同时也是"火力阻挡物"

例如：

```text
256
=
4颗 × 64 Damage
```

如果其中一颗64碰到：

```text

```

```text

```

因此RewardBall虽然提供成长资源：

同时也可能：

```text
严重降低本Turn有效火力
```

这是正式玩法的一部分。

不要优化掉。
