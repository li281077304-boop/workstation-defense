# 植物合成防线 · 开发日志

> 目标：完全本地、无广告、面向 Android 的自用游戏原型。当前实现为 Phaser 3 + TypeScript 灰盒规则验证版；Android 包装、安装包与真机触控验证尚未开始。

## 2026-08-27｜项目初始化与灰盒规则落地

### 完成

- 创建 Vite + TypeScript + Phaser 3 本地工程，建立纯 TypeScript 的 `TurnManager` 与 Phaser 场景分层。
- 实现 5 行、2 列防守区、10 列战场、出生槽，以及拖放移动、同级合成、异级交换与出生槽直合。
- 固化回合顺序：合法操作 → 操作后棋盘全体攻击 → 命中/奖励/死亡/计分 → 敌人前进 → 越过防守区即失败。
- 实现 1×1 敌人与共享 HP 的 2×2 敌人；击杀按敌人最大 HP 计分。
- 新增灰盒调试按钮：重开、生成 1×1、生成 2×2、生成奖励球。

### 规则更新：Android Projectile 实测

- 删除早期 `log2(value)` 可见子弹数、整条路伤害池、伤害模式切换和护甲猜测。
- 每株植物独立生成 `min(value, 4)` 颗 Projectile，每颗初始伤害为 `value / projectileCount`。
- Projectile 逐颗从左向右处理目标：敌人只消耗所需伤害，剩余伤害继续穿透；奖励球被命中即捕获，并销毁整颗 Projectile 的全部剩余伤害。
- 已覆盖实测：`32 → RewardBall 4 → Enemy 99`，首颗 8 伤害子弹被球阻挡，敌人最终为 75 HP。

## 从《时光拼图》项目吸取的执行原则

- **规则引擎与界面分离**：核心 TurnManager 保持不依赖 Phaser，便于单测、后续 Android 包装与复现问题。
- **拖放只结算一次**：拖动期间只保留输入状态，松手时才提交一个操作与一个 Turn，避免出现双倍操作。
- **每轮反馈驱动修复**：把用户实测的新规则立即写入日志、单测和 `OPEN_QUESTIONS.md`，防止“已确认规则”退回猜测。
- **优先验证关键交互**：Android 阶段必须以模拟器/真机实测拖放、回合触发、恢复与安装包为验收，而不只看编译通过。

- 用户确认以原版电视横屏体验为准，固定为 16:9、1920×1080 逻辑画布；此前的 1080×1920 竖屏草案废弃。
